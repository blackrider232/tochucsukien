# UI kit and shell audit

Audited commit `a52c5eb` on 2026-11-04. Scope is `src/components/ui/**`, `src/components/shell/**`, `src/app/globals.css`, the three layouts, `/dev/kit`, and the shell under `SCE_DEV_MEMORY=1` at `/` and `/dev/role`. No feature screen is on this base yet, so none was audited.

Screenshots live in `/private/tmp/claude-501/-Users-ngotuananh-ProjectCode-SEC-tochucsukien/f9cf2612-e9a6-4262-826e-d594e5255aff/scratchpad/audit-kit/` (called `SHOTS/` below). `SHOTS/README.txt` says which tool took which capture.

## Summary

**Verdict.**

1. The token layer is sound: one palette, semantic surface and ink tokens, one focus ring, three radii, three shadows, and no raw hex in components.
2. The kit is a calmer, more consistent version of the legacy app. Gradients, glass, emoji status and `shadow-2xl` are gone, and the sidebar keeps the legacy slate-900 rail users know.
3. It is not ready to hand to nine workers. Event context has no home, several primitives every module needs are missing, and the icon set is too small to replace the legacy emoji.
4. Status colour bypasses the tokens (raw `red-*` in six files), and input borders fail WCAG 1.4.11 in both themes.
5. The phone experience (DataTable cards, a two-row top bar, 40 px targets) is the weakest part for live check-in.

**Top 10 fixes, in order.**

1. Ship `src/app/(app)/events/[eventId]/layout.tsx` that renders `EventHeader` with `EventSwitcher`, and show the event name in the top bar (UI-01).
2. Add the missing primitives before workers start: link-styled `Button` (`href`), `Textarea`, `RadioGroup`, `Switch`, `Alert`, a DataTable `loading` state, a row-actions menu (UI-02).
3. Extend `IconName` to cover the legacy emoji meanings, and ban emoji and direct `lucide-react` imports in features (UI-03).
4. Add `--danger`, `--success` and `--warning` tokens and replace every raw `red-*`/`amber-*` class in the kit (UI-04).
5. Add a `--control-border` token that reaches 3:1 for inputs, selects and the combobox (UI-05).
6. Give controls inside the dark sidebar their own colour; the drawer close button is 2.36:1 today (UI-06).
7. Make `hideOnMobile` hide, collapse the mobile card row, and drop `maxHeight` below `md` in DataTable (UI-08).
8. Stop accent buttons from turning neon in dark mode, and keep Button accents to confirm tones only (UI-07).
9. Fix the three alignment bugs workers will copy: toned row shift, header baseline, KpiCard-as-button centring (UI-09, UI-10, UI-11).
10. Keep the phone top bar to one 56 px row and raise `--touch` to 44 px on coarse pointers (UI-22, UI-23).

## Rules the module workers must follow

Paste this block into every module brief.

```
UI rules (from docs/rewrite/audits/ui-kit-audit.md)
1. Import UI only from '@/components/ui'. Never deep-import a kit file or an icon pack.
2. Colour only through token classes: bg-surface/-2/-3, bg-app, text-ink/-2/-muted, border-line/-strong, bg-primary.
   No palette classes (red-600, slate-500, blue-*), no hex, no arbitrary values ([..px], [#..]).
3. Status colour comes from a vocab registry through <StatusBadge>. Never pick a tone per screen.
4. No emoji anywhere in UI text or labels. Use <Icon name> or <Badge icon>. Missing icon: ask the lead.
5. One primary Button per view. Button accent only for confirm tones (emerald, amber). Never paint a module colour on buttons.
6. Destructive actions: useDialogs().confirm({ tone: 'danger' }), never window.confirm, never a custom modal.
7. Forms: useZodForm + <Form> + <FormField> + kit controls. No raw <input>, <select>, <textarea>.
8. Lists: <FilterBar> above <DataTable>. Set hideOnMobile on every column a phone does not need.
   Empty state through DataTable.empty with an action. Give every row a stable rowKey.
9. Page sections are <SectionCard>. Do not nest cards in cards, do not add your own border or shadow.
10. Never render <main> or <h1>. The shell owns both. Your first heading is h2 (SectionCard does this).
11. Event pages render inside the event layout. Do not build your own event header or switcher.
12. Feedback: useToast() for results, inline FormField errors for input, confirm for irreversible actions.
13. Vietnamese copy: sentence case, no CAPS labels. Old-style tone marks: Xóa, Hủy, Khóa.
    Buttons are verbs ("Lưu", "Thêm khách", "Xuất Excel"). Errors say what to do ("Nhập họ tên").
14. Every icon-only control is <IconButton label="…">. The label is the Vietnamese action.
15. Check every screen at 360 px and 1440 px, light and dark, with keyboard only, before review.
16. Phone screens (live check-in): no horizontal scroll, no nested scroll areas, one action per row.
17. Need a primitive the kit lacks? Stop and ask the lead. Do not hand-roll it in your feature.
```

## Stageshow rules applied and not applied

**Applied**, as they transfer to a real app: restraint and one accent (UI-07, UI-17), quiet is not faint (UI-05, UI-29), the hero isn't outlined (UI-16), icons from one set with no emoji (UI-03), no glow or blur without a reason (UI-07, UI-26), sentence case over capitals (UI-18), columns line up and no near-tangents (UI-09, UI-10), a control hugs its content and labels centre on letters (UI-11), status colour stays legible (UI-12, UI-21), build once and check every look (both themes throughout).

**Not applied**, because they govern faux marketing scenes: bars as filler and word budgets (a real app shows real data), framing, crop and stage composition, cursor choreography and the motion timing tables, device and window chrome, "no real headings" (a real app needs a heading outline), product-name and masthead rules, the bento and page-of-demos rules, `text-box: trim` centring (worth a later look, not a defect here), and the advice to pick an icon set on purpose (the product already chose Lucide, which is fine).
